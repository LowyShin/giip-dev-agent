# 요청 해석 검증 (Request Comprehension)

Paperthin의 핵심 검증 아이디어를 GIIP PDCA 흐름에 맞게 통합한다.

## 핵심 규칙
1. 작업 시작 전 사용자 요청을 내부적으로 재해석하고, 아래와 대조한다.
   - 현재 대화 맥락
   - 프로젝트 문서
   - `.agent/rules/` 규칙
2. 문맥으로 충분히 판단 가능하면 즉시 진행한다.
3. 결과가 달라지는 **모호성만** 한 번에 **한 가지씩** 질문한다.
4. 대규모 작업은 해석 결과를 아래 형식으로 기록한다.
   - `understood as: <재해석된 요구사항>`

## 사실 검증 규칙
- 외부 사양/API/라이선스/가격/보안 기준/클라우드 정보는
  - 공식 문서 URL, 또는
  - 실제 실행 로그/결과
  를 근거로 확인한다.
- 검증되지 않은 정보는 사실처럼 단정하지 않고 `추정`으로 명시한다.

## 기록 위치 (권장)
- Plan/Design/Report 등 PDCA 산출물의 "가정/해석" 섹션
- 대화 내 진행 보고

## Why
- 초기 해석 오류를 줄이고, 대규모 작업에서 요구사항 드리프트를 방지한다.
- 검증 근거를 남겨 재현 가능성과 책임성을 높인다.
