# 아티팩트 위생 규칙 (Artifact Hygiene)

중복·노후 규칙 누적을 막고, 정본(SoR)을 명확히 유지한다.

## 정본 분리
- `.agent/rules/`: 실행 규칙의 정본
- `GEMINI.md`: 규칙 인덱스(목차)
- `README*`: 사용자 설명(정책 상세 규칙을 중복 기재하지 않음)
- 도구별 설정 파일: 해당 도구의 차이점만 기록

## 중복/노후 정리
완료 전 아래를 점검한다.
1. 동일 규칙이 여러 파일에 중복 서술되어 있는가?
2. 오래된 설정/절차가 남아 있는가?
3. 현재 사용하지 않는 항목이 남아 있는가?

중복 설명은 제거하고 정본 문서로 링크한다.

## 반복 작업 개선 (PDCA 유지)
각 반복 종료 시 최소 다음 4가지를 기록한다.
- 성공한 방법
- 실패 원인
- 다시 사용하면 안 되는 접근
- 다음 단계에서 유지할 원칙

실패한 구현을 계속 수정하는 비용이 재작성보다 크면 새 버전으로 재구현한다.

## 범위 제외 (중복 기능)
아래 항목은 GIIP 기존 기능과 중복되므로 별도 도입하지 않는다.
- `re0-loop`
- `re0-plan`
- `re0-work`
- `modelchk`
- `re0-git`
- `re0-release`
- `re0-merge`

Paperthin 전역 설치/자동 업데이트는 사용하지 않고, 필요한 내용만 저장소 내부 규칙으로 버전 고정 관리한다.

## Paperthin debloat + detool + reorder 통합

### Debloat
Rule, Role, Skill, 문서를 수정할 때:
- 같은 의미를 두 번 설명하지 않는다.
- 예시가 규칙보다 길어지지 않게 한다.
- 실행에 영향을 주지 않는 설명은 삭제한다.
- 오래된 결정 과정은 현재 정본 문서에서 제거한다.
- 현재 사실만 남긴다.

### Detool
장기 보존되는 설계 문서는 제품명과 메커니즘을 구분한다.

예:
`Redis가 필요하다`

보다

`공유 low-latency ephemeral cache가 필요하며 현재 구현체로 Redis를 사용한다`

처럼 작성한다.

단, 실제 설치법, 코드, 배포 설정, 운영 runbook에서는 정확한 제품명을 그대로 사용한다.

### Reorder
목록의 순서가 반복 수정으로 흐트러졌다면 새로운 설명을 추가하지 말고 기존 항목을 논리적 실행 순서로 재배치한다.
